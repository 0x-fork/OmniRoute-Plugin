## ដំឡើង janitor (តែម្តងប៉ុណ្ណោះ នៅលើម៉ាស៊ីន)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root)៖ រៀងរាល់ 30 នាទី កត់ត្រា log ទៅ /var/log/runner-janitor.log
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

តម្រូវឱ្យមាន `lsof`៖ janitor បញ្ជាក់ថា path មួយទំនេរដោយប្រើ snapshot មួយនៃឯកសារដែលកំពុងបើក
មុនពេលលុបវា ហើយបើគ្មានឧបករណ៍នេះ វាមិនលុបអ្វីទាំងអស់ និងជូនដំណឹងអំពីរឿងនេះ
(exit 1)។ សាកល្បងការផ្លាស់ប្តូរណាមួយជាមួយ `--dry-run` ជាមុន — វាបង្ហាញយ៉ាងជាក់លាក់នូវអ្វីដែលវានឹង
ធ្វើ ហើយមិនប៉ះពាល់អ្វីទាំងអស់។

អ្វីដែលវាធ្វើរាល់ពេលដំណើរការ៖ សម្អាតសំណល់របស់យើងផ្ទាល់ (`runner-*`, `omniroute-*`,

checkout ដែលមានអាយុ 48 ម៉ោងរបស់ runner ដែល unit របស់វា **បានឈប់**; ជូនដំណឹងនៅពេលថាស ≥ 85 %, memory PSI

## ឯកតា Runner: KillMode

`KillMode=process` លំនាំដើមរបស់ runner ទុកឱ្យ `Runner.Worker → npm → next-build`
បន្តដំណើរការនៅពេលឯកតាមួយត្រូវបានបញ្ឈប់ ឬចាប់ផ្ដើមឡើងវិញ — build ដែលក្លាយជាដំណើរការកំព្រានៅតែបន្តប្រើប្រាស់ RAM និង
CPU ដោយមិនមាន job ភ្ជាប់ជាមួយ។ ឯកតា OmniRoute នីមួយៗមាន drop-in មួយ
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ជាមួយ `KillMode=mixed`៖ ផ្ញើ SIGTERM ទៅ listener ជាមុនសិន ហើយបន្ទាប់មកផ្ញើ SIGKILL ទៅ cgroup ទាំងមូលនៅពេល
`TimeoutStop`។ វានឹងមានប្រសិទ្ធភាពនៅពេលឯកតានោះចាប់ផ្ដើមឡើងវិញលើកបន្ទាប់ — ចាប់ផ្ដើមឡើងវិញ **ម្ដងមួយ runner
ប៉ុណ្ណោះ ហើយតែនៅពេលទំនេរ** ដោយដាក់ការត្រួតពិនិត្យភាពទំនេរ និងការចាប់ផ្ដើមឡើងវិញនៅក្នុង command តែមួយ។
