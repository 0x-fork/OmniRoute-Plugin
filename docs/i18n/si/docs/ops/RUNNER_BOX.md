## janitor ස්ථාපනය කරන්න (එක් වරක් පමණක්, යන්ත්රය මත)

```bash
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` අවශ්ය වේ: janitor විසින් path එකක් ඉවත් කිරීමට පෙර, විවෘත files පිළිබඳ එක් snapshot එකක් භාවිතයෙන් එය අක්රිය බව තහවුරු කරයි; එම tool එක නොමැතිව එය කිසිවක් ඉවත් නොකරන අතර ඒ බව දන්වයි
(exit 1). ඕනෑම වෙනසක් පළමුව `--dry-run` සමඟ අත්හදා බලන්න — එය සිදු කිරීමට නියමිත දේ නිවැරදිව මුද්රණය කරන අතර කිසිවක් වෙනස් නොකරයි.

එක් එක් ධාවනයේදී එය කරන දේ: **tmpfs මත පැය 3කට** පසු සහ disk
`_work/_temp` මත පැය 24කට පසු අපගේම ඉතිරි දෑ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ඉවත් කරයි; මිනිත්තු 75කට වඩා පැරණි `next-build` එකක් නවත්වයි (කිසිදු job එකක් එතරම් දිගු කාලයක් ක්රියාත්මක නොවේ — 2026-08-27 දින GitHub විසින් එහි job එක අහිමි වූ බව ප්රකාශ කිරීමෙන් පසුවත් එකක් මිනිත්තු 70ක් ක්රියාත්මක විය); unit එක **නවතා ඇති** runners සඳහා පැය 48කට වඩා පැරණි checkouts ඉවත් කරයි; disk ≥ 85 %, memory PSI
`full/avg60` ≥ 10 %, සහ `MAX_ACTIVE_RUNNERS` ට වඩා listeners සිටින විට (omniroute/other බෙදීමක් සමඟ) අනතුරු අඟවයි. Exit 1 = අවධානය අවශ්යයි; log එක කියවන්න.

## Runner ඒකක: KillMode

Runner හි පෙරනිමි `KillMode=process` සැකසුම නිසා ඒකකයක් නතර කළ හෝ නැවත ආරම්භ කළ විට `Runner.Worker → npm → next-build` ක්රියාවලි සජීවීව පවතී — අමුණා ඇති job එකක් නොමැති අනාථ build එකක් RAM සහ CPU දිගටම පරිභෝජනය කරයි. සෑම OmniRoute ඒකකයකම `KillMode=mixed` සහිත drop-in එකක් (`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`) ඇත: පළමුව listener වෙත SIGTERM යවන අතර, `TimeoutStop` අවස්ථාවේදී සම්පූර්ණ cgroup එක වෙත SIGKILL යවයි. එය ඒකකයේ ඊළඟ නැවත ආරම්භයේදී ක්රියාත්මක වේ — idle පරීක්ෂාව සහ නැවත ආරම්භ කිරීම එකම command එක තුළ තබා, **වරකට එක් runner එකක් පමණක්, එය idle වූ විට පමණක්** නැවත ආරම්භ කරන්න.
