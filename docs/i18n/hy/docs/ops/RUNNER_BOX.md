Ինքնուրույն հոսթավորվող փուլը գործում է **.113** մեքենայի վրա (`tomni-proxmox-113`)։ 2026-10-18-ից սկսած՝
OmniRoute-ի յուրաքանչյուր ռաններ ունի **մեկ դեր**, մեկ պիտակ և հիշողության/CPU-ի բյուջե՝ իր ծանրաբեռնվածության

համապատասխանում են դրանց չափված առավելագույններին։ Մեքենայի ռեսուրսները գերբաշխվում են միայն այն ժամանակ, երբ Turbopack-ի բիլդը համընկնում է Release-Green-ի

## Տեղադրեք մաքրիչը (մեկ անգամ՝ սերվերի վրա)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root)՝ յուրաքանչյուր 30 րոպեն մեկ, գրանցել /var/log/runner-janitor.log-ում
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof`-ը պարտադիր է. մաքրիչը, նախքան որևէ ուղի հեռացնելը, բաց
ֆայլերի մեկ ակնթարթային պատկերով ապացուցում է, որ այն պարապ է, իսկ առանց այս գործիքի
ոչինչ չի հեռացնում և հայտնում է այդ մասին (exit 1)։ Ցանկացած փոփոխություն նախ փորձարկեք
`--dry-run`-ով. այն հստակ տպում է, թե ինչ կաներ, և ոչինչ չի փոփոխում։

Ինչ է անում յուրաքանչյուր գործարկման ժամանակ. մաքրում է մեր թողած մնացորդները (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`)՝ **tmpfs-ում 3 ժամ**, իսկ սկավառակի
`_work/_temp`-ում՝ 24 ժամ անց, դադարեցնում է 75 րոպեից հին `next-build`-ը (ոչ մի առաջադրանք
այդքան երկար չի աշխատում. 2026-08-27-ին դրանցից մեկն աշխատել է 70 րոպե այն բանից հետո, երբ
GitHub-ն իր առաջադրանքը կորած էր հայտարարել), մաքրում է այն runner-ների 48 ժամից հին
աշխատանքային պատճենները, որոնց unit-ը **դադարեցված է**, և նախազգուշացնում է, երբ սկավառակի
օգտագործումը ≥ 85 % է, հիշողության PSI-ի `full/avg60`-ը ≥ 10 % է, կամ listener-ների քանակը
գերազանցում է `MAX_ACTIVE_RUNNERS`-ը (omniroute/այլ տարանջատմամբ)։ Exit 1 = ուշադրություն է
պահանջվում. կարդացեք log-ը։

75 րոպեի կանոնը չի հայտնաբերում այն build-ը, որի առաջադրանքից GitHub-ն արդեն հրաժարվել է։ Երբ
`Runner.Listener`-ը չի կարողանում թարմացնել իր առաջադրանքը, `_diag/Runner_*.log`-ում երևում է
`POST request to …/renewjob timed out after 100 seconds`, API-ն վերջին հաջող թարմացումից մոտ տասը
րոպե անց առաջադրանքը հաղորդում է որպես `completed` (ձախողված), իսկ `next-build`-ը շարունակում է
աշխատել՝ առանց կցված առաջադրանքի (2026-10-18-ին #17066-ի Build-ը 19:43-ին նշվել է որպես ձախողված,
իսկ դրա build-ը հինգ րոպե անց դեռ զբաղեցնում էր 40 GB)։ Հաստատեք ref-ը ամենանոր
`_diag/Worker_*.log`-ում, ապա PID-ով SIGTERM ուղարկեք միայն build-ի ծառին՝ `next-build`,
`npm run build`, `build-next-isolated.mjs` և `_work` worker-ներին։ Երբեք մի՛ դիպչեք
`Runner.Listener`-ին, `RunnerService.js`-ին կամ `Runner.Worker`-ին. worker-ը առաջադրանքը հաղորդում
է որպես չեղարկված, իսկ listener-ն ինքնուրույն կրկին անցնում է առցանց վիճակի։

## Runner unit-ներ. KillMode

Runner-ի լռելյայն `KillMode=process`-ը unit-ի դադարեցման կամ վերագործարկման դեպքում
`Runner.Worker → npm → next-build`-ը թողնում է աշխատող. որբացած build-ը շարունակում է սպառել
RAM և CPU՝ առանց կցված առաջադրանքի։ OmniRoute-ի յուրաքանչյուր unit ունի drop-in
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)՝
`KillMode=mixed`-ով. նախ SIGTERM է ուղարկվում listener-ին, ապա `TimeoutStop`-ի պահին՝ SIGKILL
ամբողջ cgroup-ին։ Այն ուժի մեջ է մտնում unit-ի հաջորդ վերագործարկումից հետո. վերագործարկեք
**միաժամանակ միայն մեկ runner և միայն երբ այն պարապ է**՝ պարապ լինելու ստուգումն ու
վերագործարկումը կատարելով նույն հրամանով։
