Il-pool self-hosted jaħdem fuq il-magna **.113** (`tomni-proxmox-113`). Mill-2026-10-18 kull
runner ta' OmniRoute għandu **rwol wieħed**, label waħda, u baġit tal-memorja/CPU adattat għal dak li
tkejjel fil-workload tiegħu. Is-slot ta' Turbopack jingħata dak li teħtieġ il-build; is-slots l-oħra huma
adattati għall-ogħla livelli mkejla tagħhom. Il-magna tagħmel overcommit biss meta build ta' Turbopack
tikkoinċidi ma' build webpack ta' Release-Green u job tal-lint; is-swap tal-host (16 GB) jassorbi dan,
u peress li l-Builds tal-pull requests jaħdmu fuq runners hosted, is-slot ta' Turbopack ikun inattiv
il-biċċa l-kbira tal-ħin:

## Installa l-janitor (darba waħda, fuq il-magna)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): kull 30 minuta, illoggja f’/var/log/runner-janitor.log
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` huwa meħtieġ: il-janitor jivverifika li path mhux qed jintuża permezz ta’ snapshot waħda tal-fajls miftuħa qabel ineħħih, u mingħajr din l-għodda ma jneħħi xejn u jgħid dan
(exit 1). L-ewwel ipprova kwalunkwe bidla b’`--dry-run` — jistampa eżattament x’jagħmel
u ma jmiss xejn.

X’jagħmel ma’ kull tħaddim: inaddaf ir-residwi tagħna stess (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) wara **3 sigħat fuq tmpfs** u 24 siegħa fuq id-disk
`_work/_temp`; iwaqqaf `next-build` eqdem minn 75 minuta (l-ebda job ma jdum daqshekk — fl-
2026-08-27 wieħed dam 70 minuta wara li GitHub kien iddikjara l-job tiegħu mitluf); ineħħi checkouts
li għandhom 48 siegħa ta’ runners li l-unità tagħhom hija **wieqfa**; joħroġ twissijiet meta d-disk ikun ≥ 85 %, il-PSI
tal-memorja `full/avg60` ikun ≥ 10 %, u jkun hemm aktar listeners minn `MAX_ACTIVE_RUNNERS` (b’analiżi
bejn omniroute/u oħrajn). Exit 1 = jeħtieġ attenzjoni; aqra l-log.

Ir-regola tal-75 minuta ma taqbadx build li GitHub ikun diġà qata’ qalbu minnu. Meta
`Runner.Listener` ma jkunx jista’ jġedded il-job tiegħu, `_diag/Runner_*.log` juri
`POST request to …/renewjob timed out after 100 seconds`, l-API tirrapporta l-job bħala `completed`
(failure) madwar għaxar minuti wara l-aħħar tiġdid li rnexxa, u `next-build` jibqa’ jaħdem mingħajr
job marbut miegħu (2026-10-18: il-Build ta’ #17066 falla fid-19:43 u l-build tiegħu kien għadu
qed iżomm 40 GB ħames minuti wara). Ikkonferma r-ref fl-aktar `_diag/Worker_*.log` ġdid, imbagħad
ibgħat SIGTERM biss lis-siġra tal-build skont il-PID — `next-build`, `npm run build`, `build-next-isolated.mjs` u
l-workers ta’ `_work`. Qatt tmiss `Runner.Listener`, `RunnerService.js` jew `Runner.Worker`: il-
worker jirrapporta l-job bħala kkanċellat u l-listener jerġa’ jiġi online waħdu.

## Unitajiet tar-runner: KillMode

Il-`KillMode=process` predefinit tar-runner iħalli `Runner.Worker → npm → next-build`
jaħdem meta unità titwaqqaf jew terġa’ tinbeda — build orfni jibqa’ jikkonsma RAM u
CPU mingħajr job marbut miegħu. Kull unità ta’ OmniRoute għandha drop-in
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
b’`KillMode=mixed`: SIGTERM lil-listener l-ewwel, u SIGKILL liċ-cgroup kollu meta jintlaħaq
`TimeoutStop`. Dan jidħol fis-seħħ mar-restart li jmiss tal-unità — erġa’ ibda **runner wieħed
kull darba, u biss meta ma jkunx qed jintuża**, bil-kontroll li mhuwiex qed jintuża u r-restart fl-istess command.

## Regoli operattivi

- **Build wieħed ta’ Turbopack kull darba — infurzat permezz ta’ tikketta.** Kull job li jħaddem
  `next build` sħiħ ta’ Turbopack jimmira lejn `[self-hosted, omni-build]`, u **`omniroute-113-5`**
  biss għandu dik it-tikketta: `ci.yml` `Build`, `npm-publish.yml` `publish`, `nightly-v4-build`,
  `preview-artifact`, il-build a11y ta’ billejl (#16853) u **amd64** ta’ `docker-publish.yml`
  (webpack ġewwa BuildKit — Turbopack iġġarraf hemmhekk, run 33253576569). Il-parti arm64 ta’
  Docker tibqa’ fuq `ubuntu-24.04-arm`. amd64 ta’ `docker-publish` jaqsam il-grupp ta’ konkorenza
  `heavy-build-main` ma’ `ci.yml` `Build` (`cancel-in-progress: false`). Docker Engine irid ikun
  fuq `omniroute-113-5`. It-tieni slot ta’ Turbopack ma joqgħodx f’78 GB (2 × 33–37 GB flimkien
  mal-bqija tal-magna); it-tieni slot huwa sikur biss għal builds ta’ webpack.
- **Il-Builds tal-pull requests jitħaddmu fuq infrastruttura ospitata (2026-10-18).** `ci.yml`
  `Build` jilħaq `omni-build` biss għal `push` u `workflow_dispatch`; kull Build ta’
  `pull_request` (mill-istess oriġini jew minn fork) u `merge_group` jitħaddem fuq
  `ubuntu-latest` b’webpack. Meta kull PR mill-istess oriġini kien jintbagħat lejn is-slot, Build
  ta’ Turbopack kien iżommu għal 29–58 min, 18-il Build damu fil-kju sa 18-il siegħa, u l-Build
  tal-`push` tal-linja tar-rilaxx stess kiseb is-slot darba biss f’40 job. Fuq l-infrastruttura
  ospitata, l-istess Build tal-PR jieħu 8–12-il min flimkien mal-jobs l-oħra tal-PR. Turbopack,
  il-bundler li jqassam `npm-publish`, jibqa’ jiġi eżerċitat fuq il-linja tar-rilaxx mill-build
  a11y ta’ billejl tal-fergħa predefinita (04:41 UTC), minn kull Build ta’ push jew dispatch li
  jilħaq is-slot, u minn `npm-publish` stess. `tests/unit/build/heavy-build-queue.test.ts`
  jistabbilixxi l-kontroll b’erba’ kundizzjonijiet.
- **Qatt tnaqqas is-slot ta’ Turbopack għal inqas mill-ħtieġa mkejla tiegħu.** Fit-2026-10-18
  fis-18:06 is-slot tnaqqas minn 56G/60G għal 40G/44G biex jagħmel spazju għal `omni-release`.
  Il-fażi tal-kompilazzjoni baqgħet fil-`MemoryHigh` matul ir-run kollu tagħha (memory PSI `full`
  ta’ 30–43 %), u `Runner.Listener`, li jaqsam l-istess cgroup, ma setax iġedded il-job tiegħu.
  Is-56G/60G tas-sid mill-2026-10-17 ġew restawrati dakinhar stess. Taħt dak il-valur il-build ma
  jfallix; jibda jitħabat minħabba ċaqliq kontinwu tal-memorja, u l-job jintilef.
- **Release-Green għandu s-slot tiegħu stess (2026-10-18).** Sa dak iż-żmien iż-żewġ
  validazzjonijiet ta’ Release-Green kienu jitħaddmu fuq `omni-build`: ma’ kull push
  (~10 fis-siegħa, 97 minn 100 run ta’ push ikkanċellati waqt ix-xogħol f’ġurnata waħda) u tliet
  sweeps sħaħ ta’ ~2 sigħat kuljum (is-sweep tal-05:29 stenna 6 sigħat għas-slot) — l-uniku slot
  tal-build kien ibbukkjat b’domanda ferm ogħla mill-kapaċità tiegħu u l-Builds tal-PRs
  mill-istess oriġini stennew għal sigħat. `release-green` u `main-green` issa jimmiraw lejn
  `omni-release` (`omniroute-113-6` biss) b’`OMNIROUTE_USE_TURBOPACK=0`, u run li jkun beda ma
  jibqax jiġi kkanċellat minn push aktar ġdid (is-slot pendenti xorta jikkonsolida l-maltempata).
  `tests/unit/build/runner-capacity-routing.test.ts` jistabbilixxi r-routing, il-bidla għal webpack
  u li xejn fuq `omni-release` ma jinbena b’Turbopack.
- **Pool ħafif: `omni-light`.** `omniroute-113` u `omniroute-113-2` iħaddmu l-jobs ta’ billejl li
  jeħtieġu `next build` għall-backend biss (~5–6 GB; webpack) u `quality.yml` `lint-guard`.
  `omniroute-113` kellu `MemoryHigh=4G` sal-2026-10-18 — il-build ta’ promptfoo għamel 54 minuta
  javvanza permezz tal-irkupru tal-memorja hemmhekk; 8 GB jeliminaw it-throttling.
- **Inqas listeners apposta.** Erba’ units ta’ OmniRoute ġew diżattivati fl-2026-08-29 — kull
  listener addizzjonali huwa konsumatur ieħor tal-baġit tal-memorja msemmi hawn fuq. Il-limitu
  massimu tal-janitor huwa 6 (`MAX_ACTIVE_RUNNERS=6` fil-cron): jgħodd kull `Runner.Listener`
  fuq il-magna, u OmniHeuris + OmniMind iżidu tnejn mal-erbgħa tagħna.
- **Qatt tnaddaf `/tmp` jew `_work` bl-idejn waqt li xi runner ikun okkupat.** Kontroll segwit
  minn tħassir, b’intervall bejn it-tnejn, kien il-mod kif job `Build` attiv tilef il-`_work`
  tiegħu fl-2026-08-27. Il-janitor jagħmel il-kontroll u t-tneħħija f’pass wieħed;
  ħallih jagħmilhom.
- Il-waqfien ta’ runner waqt job jikkanċella l-job (osservat direttament): uża `systemctl stop`
  biss meta l-listener tiegħu ma jkollux child `Runner.Worker` — u agħmel dan bi kmand wieħed.
- Il-workflows ma għandhomx ipoġġu artefatti f’`/tmp` (huwa RAM). Niżżel lejn
  `$RUNNER_TEMP` (fuq id-diska, għal kull runner) — l-artefatt `next-build` ta’ 1.3 GB ħa 27–32
  minuta biex jitniżżel fuq it-tmpfs u 2 minuti biex jittella’ mid-diska.
- Il-VPS `.15` huwa għall-omologazzjoni biss — qatt ma jħaddem CI runners.

## Korsija ospitata (runners ospitati minn GitHub)

Il-kont qiegħed fuq il-pjan **Pro**: **40 kompitu ospitat konkorrenti**, kondiviżi minn kull kontroll ta’ PR,
kull workflow attivat minn push u l-konfigurazzjoni predefinita ta’ CodeQL. Imkejjel fit-2026-10-18 waqt
kampanja ta’ merges (~10 merges/siegħa fuq `release/v3.8.52`): **2,500 eżekuzzjoni ta’ workflows inħolqu fi
24 siegħa**, 44 push lejn il-branch f’6 sigħat, **106 kompiti ospitati fil-kju** waqt li l-kontrolli tal-PR stennew għal
sigħat u l-PRs ġew merged mingħajrhom. Disa’ workflows ġew attivati ma’ kull push lejn il-branch:

| għal kull push lejn `release/v*`                   | kompiti ospitati | riżultat matul il-maltempata                                            | mill-2026-10-18                                                                      |
| -------------------------------------------------- | ---------------: | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `ci.yml` (matriċi sħiħa)                           |      sa mass. 30 | ikkanċellat mill-push ta’ wara, 24 minn 24 f’jum                        | ma jinbediex fuq pushes lejn `release/**` (eżekuzzjoni tal-PR + Release-Green)       |
| `quality.yml`                                      |               ~6 | ikkanċellat, 23 minn 23                                                 | ma jinbediex fuq pushes lejn `release/**`                                            |
| `Release-Green` `--quick`                          |                0 | ġera fuq `omni-build`, 97 minn 100 ġew ikkanċellati                     | slot `omni-release`, qatt ma jiġi kkanċellat, l-eżekuzzjonijiet pendenti jingħaqdu   |
| `Lock released branch`, `OpenSSF Scorecard`        |                2 | eżekuzzjoni waħda fil-kju għal kull push                                | eżekuzzjoni waħda għal kull ref (`tests/unit/build/hosted-lane-concurrency.test.ts`) |
| `Release acceptance` (rapport parallel)            |                1 | `npm ci` ospitat wieħed għal kull push, qatt ma jiġi kkanċellat         | mhux mibdul — kandidat għal filtru `paths:`                                          |
| `Publish to Docker Hub` → `Deploy to VPS`          |                2 | ikkanċellati għal kull push; il-parti amd64 tikkompeti fuq `omni-build` | mhux mibdul — il-kanal ta’ deploy tas-sid                                            |
| Konfigurazzjoni predefinita ta’ CodeQL (`dynamic`) |                4 | `javascript-typescript`, `actions`, `c-cpp`, `python` għal kull push    | mhux mibdul — Settings → Code security; `c-cpp`/`python` ma jiskennjaw xejn hawn     |

`tests/unit/build/push-storm-diet.test.ts` jiffissa t-trigger tal-push għal `main` biss ta’ `ci.yml` u
`quality.yml`. Effett sekondarju: Codecov ma jibqax jirċievi upload bażi għal kull push tar-release (il-
pass huwa informattiv u għandu `continue-on-error`); il-kontroll tal-coverage fir-repo u l-kumment fuq il-PR
mhumiex affettwati.

**Aktar kapaċità self-hosted ma ssolvix il-kju ospitat.** Id-devbox
(`devbox-vm-06-dev002`, 24 vCPU / 54 GB) jista’ jospita runner, iżda s-sessjonijiet tal-aġenti diġà
