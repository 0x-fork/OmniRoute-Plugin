ಯಾವುದೇ jobಗೆ ಪರಿಣಾಮವಾಗಿಲ್ಲ. Labels ಅನ್ನು runners API ಮೂಲಕ

`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`) ಬದಲಾಯಿಸಲಾಗುತ್ತದೆ, ಇದನ್ನೂ ಚಾಲನೆಯಲ್ಲಿರುವಾಗಲೇ ಮಾಡಲಾಗುತ್ತದೆ.

## ಜ್ಯಾನಿಟರ್ ಅನ್ನು ಸ್ಥಾಪಿಸಿ (ಒಮ್ಮೆ ಮಾತ್ರ, ಯಂತ್ರದಲ್ಲಿ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ಪ್ರತಿ 30 ನಿಮಿಷಕ್ಕೊಮ್ಮೆ, /var/log/runner-janitor.log ಗೆ ಲಾಗ್ ಮಾಡಿ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ಅಗತ್ಯವಿದೆ: ಜ್ಯಾನಿಟರ್ ಒಂದು ಪಥವನ್ನು ತೆಗೆದುಹಾಕುವ ಮೊದಲು ತೆರೆದಿರುವ
ಫೈಲ್ಗಳ ಒಂದು ಸ್ನ್ಯಾಪ್ಶಾಟ್ ಮೂಲಕ ಅದು ನಿಷ್ಕ್ರಿಯವಾಗಿದೆ ಎಂದು ಖಚಿತಪಡಿಸುತ್ತದೆ; ಈ ಉಪಕರಣವಿಲ್ಲದಿದ್ದರೆ ಅದು ಏನನ್ನೂ ತೆಗೆದುಹಾಕುವುದಿಲ್ಲ ಮತ್ತು ಅದನ್ನು ತಿಳಿಸುತ್ತದೆ
(exit 1). ಯಾವುದೇ ಬದಲಾವಣೆಯನ್ನು ಮೊದಲು `--dry-run` ಬಳಸಿ ಪ್ರಯತ್ನಿಸಿ — ಅದು ತಾನು ನಿಖರವಾಗಿ ಏನು
ಮಾಡುವುದೆಂದು ಮುದ್ರಿಸುತ್ತದೆ ಮತ್ತು ಯಾವುದನ್ನೂ ಬದಲಾಯಿಸುವುದಿಲ್ಲ.

ಪ್ರತಿ ರನ್ನಲ್ಲಿ ಅದು ಮಾಡುವ ಕೆಲಸ: **tmpfs ನಲ್ಲಿ 3 ಗಂಟೆಗಳ** ನಂತರ ಮತ್ತು ಡಿಸ್ಕ್ನ
`_work/_temp` ನಲ್ಲಿ 24 ಗಂಟೆಗಳ ನಂತರ ನಮ್ಮದೇ ಉಳಿಕೆಗಳನ್ನು (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ತೆರವುಗೊಳಿಸುತ್ತದೆ; 75 ನಿಮಿಷಕ್ಕಿಂತ ಹಳೆಯದಾದ `next-build` ಅನ್ನು ಕೊಲ್ಲುತ್ತದೆ (ಯಾವುದೇ ಜಾಬ್ ಅಷ್ಟು ಹೊತ್ತು ನಡೆಯುವುದಿಲ್ಲ —
2026-08-27 ರಂದು GitHub ತನ್ನ ಜಾಬ್ ಕಳೆದುಹೋಗಿದೆ ಎಂದು ಘೋಷಿಸಿದ ನಂತರವೂ ಒಂದು ಜಾಬ್ 70 ನಿಮಿಷ ನಡೆಯಿತು);
ಯಾವ ರನ್ನರ್ಗಳ ಯೂನಿಟ್ **ನಿಂತಿದೆಯೋ**, ಅವುಗಳ 48 ಗಂಟೆ ಹಳೆಯ
ಚೆಕ್ಔಟ್ಗಳನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ; ಡಿಸ್ಕ್ ≥ 85 %, ಮೆಮೊರಿ PSI
`full/avg60` ≥ 10 %, ಮತ್ತು `MAX_ACTIVE_RUNNERS` ಗಿಂತ ಹೆಚ್ಚು listeners ಇದ್ದಾಗ
(omniroute/ಇತರೆ ಎಂಬ ವಿಭಜನೆಯೊಂದಿಗೆ) ಎಚ್ಚರಿಸುತ್ತದೆ. Exit 1 = ಗಮನ ಅಗತ್ಯ; ಲಾಗ್ ಓದಿ.

GitHub ಈಗಾಗಲೇ ಕೈಬಿಟ್ಟಿರುವ ಜಾಬ್ನ ಬಿಲ್ಡ್ ಅನ್ನು 75 ನಿಮಿಷದ ನಿಯಮ ಪತ್ತೆಹಚ್ಚುವುದಿಲ್ಲ.
`Runner.Listener` ತನ್ನ ಜಾಬ್ ಅನ್ನು ನವೀಕರಿಸಲು ಸಾಧ್ಯವಾಗದಾಗ, `_diag/Runner_*.log` ನಲ್ಲಿ
`POST request to …/renewjob timed out after 100 seconds` ಕಾಣಿಸುತ್ತದೆ; ಕೊನೆಯ ಯಶಸ್ವಿ ನವೀಕರಣದ ಸುಮಾರು ಹತ್ತು ನಿಮಿಷಗಳ ನಂತರ API ಜಾಬ್ ಅನ್ನು `completed`
(failure) ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ, ಮತ್ತು ಯಾವುದೇ ಜಾಬ್ ಲಗತ್ತಿಸದಿದ್ದರೂ `next-build` ಚಾಲನೆಯಲ್ಲೇ ಇರುತ್ತದೆ
(2026-10-18: #17066ರ Build 19:43ಕ್ಕೆ ವಿಫಲವಾಗಿತ್ತು ಮತ್ತು ಐದು ನಿಮಿಷಗಳ ನಂತರವೂ ಅದರ ಬಿಲ್ಡ್
40 GB ಅನ್ನು ಹಿಡಿದಿಟ್ಟುಕೊಂಡಿತ್ತು). ಅತ್ಯಂತ ಹೊಸ `_diag/Worker_*.log` ನಲ್ಲಿ ref ಅನ್ನು ದೃಢಪಡಿಸಿ, ನಂತರ
PID ಮೂಲಕ ಬಿಲ್ಡ್ ಟ್ರೀಗೆ ಮಾತ್ರ SIGTERM ಕಳುಹಿಸಿ — `next-build`, `npm run build`, `build-next-isolated.mjs` ಮತ್ತು
`_work` workers. `Runner.Listener`, `RunnerService.js` ಅಥವಾ `Runner.Worker` ಅನ್ನು ಎಂದಿಗೂ ಮುಟ್ಟಬೇಡಿ:
worker ಜಾಬ್ ಅನ್ನು ರದ್ದುಗೊಳಿಸಲಾಗಿದೆ ಎಂದು ವರದಿ ಮಾಡುತ್ತದೆ ಮತ್ತು listener ಸ್ವತಃ ಮತ್ತೆ ಆನ್ಲೈನ್ಗೆ ಬರುತ್ತದೆ.

## ರನ್ನರ್ ಯೂನಿಟ್ಗಳು: KillMode

ರನ್ನರ್ನ ಡೀಫಾಲ್ಟ್ `KillMode=process`, ಯೂನಿಟ್ ಅನ್ನು ನಿಲ್ಲಿಸಿದಾಗ ಅಥವಾ ಮರುಪ್ರಾರಂಭಿಸಿದಾಗ
`Runner.Worker → npm → next-build` ಅನ್ನು ಚಾಲನೆಯಲ್ಲೇ ಬಿಡುತ್ತದೆ — ಅನಾಥ ಬಿಲ್ಡ್ ಯಾವುದೇ ಜಾಬ್
ಲಗತ್ತಿಸದಿದ್ದರೂ RAM ಮತ್ತು CPU ಅನ್ನು ಬಳಸುತ್ತಲೇ ಇರುತ್ತದೆ. ಪ್ರತಿ OmniRoute ಯೂನಿಟ್
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ನಲ್ಲಿ `KillMode=mixed` ಇರುವ drop-in ಹೊಂದಿದೆ: ಮೊದಲು listener ಗೆ SIGTERM, ನಂತರ
