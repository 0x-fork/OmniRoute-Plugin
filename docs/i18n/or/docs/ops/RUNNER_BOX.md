ସ୍ୱୟଂ-ହୋଷ୍ଟେଡ୍ ପୁଲ୍ଟି **.113** ବକ୍ସ (`tomni-proxmox-113`) ଉପରେ ଚାଲେ। 2026-10-18 ଠାରୁ ପ୍ରତ୍ୟେକ
OmniRoute runner ପାଖରେ **ଗୋଟିଏ ଭୂମିକା**, ଗୋଟିଏ label, ଏବଂ ଏହାର workload ର ମାପାଯାଇଥିବା
ଆବଶ୍ୟକତା ଅନୁଯାୟୀ memory/CPU budget ରହିଛି। Turbopack ସ୍ଲଟ୍କୁ build ପାଇଁ ଆବଶ୍ୟକ ସମ୍ବଳ ମିଳେ;
ଅନ୍ୟ ସ୍ଲଟ୍ଗୁଡ଼ିକୁ ସେମାନଙ୍କର ମାପାଯାଇଥିବା ସର୍ବୋଚ୍ଚ ବ୍ୟବହାର ଅନୁଯାୟୀ ଆକାର ଦିଆଯାଇଛି।
କେବଳ ଯେତେବେଳେ ଗୋଟିଏ Turbopack build ସହ ଗୋଟିଏ Release-Green webpack build ଏବଂ ଗୋଟିଏ lint job
ଏକାସାଙ୍ଗରେ ଚାଲେ, ସେତେବେଳେ ବକ୍ସଟି ନିଜ କ୍ଷମତାଠାରୁ ଅଧିକ ସମ୍ବଳ ପ୍ରତିଶ୍ରୁତ କରେ; host swap (16 GB)

## ପରିଷ୍କାରକକୁ ଇନଷ୍ଟଲ୍ କରନ୍ତୁ (କେବଳ ଥରେ, ସର୍ଭର୍ରେ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ପ୍ରତି 30 ମିନିଟ୍ରେ, /var/log/runner-janitor.log ରେ ଲଗ୍ କରନ୍ତୁ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ଆବଶ୍ୟକ: କୌଣସି ପଥକୁ ଅପସାରଣ କରିବା ପୂର୍ବରୁ ପରିଷ୍କାରକ ଖୋଲା
ଫାଇଲ୍ଗୁଡ଼ିକର ଗୋଟିଏ ସ୍ନାପସଟ୍ ନେଇ ପଥଟି ନିଷ୍କ୍ରିୟ ବୋଲି ପ୍ରମାଣ କରେ, ଏବଂ ଏହି ଟୁଲ୍ ବିନା ଏହା କିଛି ଅପସାରଣ କରେ ନାହିଁ ଓ ସେକଥା
ଜଣାଏ (exit 1)। ଯେକୌଣସି ପରିବର୍ତ୍ତନକୁ ପ୍ରଥମେ `--dry-run` ସହ ପରୀକ୍ଷା କରନ୍ତୁ — ଏହା ଠିକ୍ କ’ଣ
କରିବ ତାହା ପ୍ରିଣ୍ଟ କରେ ଏବଂ କୌଣସି ଜିନିଷକୁ ସ୍ପର୍ଶ କରେ ନାହିଁ।

ପ୍ରତ୍ୟେକ ରନ୍ରେ ଏହା ଯାହା କରେ: **tmpfs ରେ 3 ଘଣ୍ଟା** ଏବଂ ଡିସ୍କ୍ର
`_work/_temp` ରେ 24 ଘଣ୍ଟା ପରେ ଆମର ନିଜସ୍ୱ ଅବଶେଷଗୁଡ଼ିକ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ସଫା କରେ; 75 ମିନିଟ୍ରୁ ପୁରୁଣା `next-build`କୁ ବନ୍ଦ କରେ (କୌଣସି ଜବ୍ ଏତେ ସମୟ ଚାଲେ ନାହିଁ —
2026-08-27 ରେ GitHub ଏହାର ଜବ୍ ହଜିଯାଇଛି ବୋଲି ଘୋଷଣା କରିବା ପରେ ଗୋଟିଏ ଜବ୍ 70 ମିନିଟ୍ ଚାଲିଥିଲା); ଯେଉଁ ରନର୍ଗୁଡ଼ିକର ୟୁନିଟ୍ **ବନ୍ଦ ଅଛି**, ସେଗୁଡ଼ିକର 48 ଘଣ୍ଟା ପୁରୁଣା
ଚେକ୍ଆଉଟ୍ଗୁଡ଼ିକୁ ଅପସାରଣ କରେ; ଡିସ୍କ୍ ≥ 85 %, ମେମୋରି PSI
`full/avg60` ≥ 10 %, ଏବଂ `MAX_ACTIVE_RUNNERS` ଠାରୁ ଅଧିକ ଲିସ୍ନର୍ ଥିଲେ (omniroute/ଅନ୍ୟ ବିଭାଜନ ସହିତ) ସତର୍କ କରେ। Exit 1 = ଧ୍ୟାନ ଦେବା ଆବଶ୍ୟକ; ଲଗ୍ ପଢ଼ନ୍ତୁ।

75-ମିନିଟ୍ ନିୟମ ସେହି ବିଲ୍ଡ୍କୁ ଚିହ୍ନଟ କରେ ନାହିଁ ଯାହାର ଜବ୍କୁ GitHub ପୂର୍ବରୁ ଛାଡ଼ି ଦେଇଛି। ଯେତେବେଳେ
`Runner.Listener` ନିଜ ଜବ୍କୁ ନବୀକରଣ କରିପାରେ ନାହିଁ, `_diag/Runner_*.log` ରେ
`POST request to …/renewjob timed out after 100 seconds` ଦେଖାଯାଏ, ଶେଷ ସଫଳ ନବୀକରଣର ପ୍ରାୟ ଦଶ ମିନିଟ୍ ପରେ API ଜବ୍ଟିକୁ `completed`
(failure) ବୋଲି ରିପୋର୍ଟ କରେ, ଏବଂ କୌଣସି ଜବ୍ ସଂଲଗ୍ନ ନ ଥାଇ `next-build` ଚାଲିଥାଏ
(2026-10-18: #17066 ର ବିଲ୍ଡ୍ 19:43 ରେ ବିଫଳ ହୋଇଥିଲା ଏବଂ ତାହାର ବିଲ୍ଡ୍ ପାଞ୍ଚ ମିନିଟ୍ ପରେ ମଧ୍ୟ
40 GB ଦଖଲ କରି ରଖିଥିଲା)। ସବୁଠାରୁ ନୂଆ `_diag/Worker_*.log` ରେ ref ନିଶ୍ଚିତ କରନ୍ତୁ, ତା’ପରେ
PID ଦ୍ୱାରା କେବଳ ବିଲ୍ଡ୍ ଟ୍ରିକୁ SIGTERM ପଠାନ୍ତୁ — `next-build`, `npm run build`, `build-next-isolated.mjs` ଏବଂ
`_work` ୱର୍କର୍ଗୁଡ଼ିକୁ। `Runner.Listener`, `RunnerService.js` କିମ୍ବା `Runner.Worker`କୁ କେବେ ସ୍ପର୍ଶ କରନ୍ତୁ ନାହିଁ:
ୱର୍କର୍ ଜବ୍ଟି ବାତିଲ୍ ହୋଇଛି ବୋଲି ରିପୋର୍ଟ କରେ ଏବଂ ଲିସ୍ନର୍ ନିଜେ ପୁଣି ଅନଲାଇନ୍ ହୋଇଯାଏ।

## ରନର୍ ୟୁନିଟ୍ଗୁଡ଼ିକ: KillMode

ରନର୍ର ଡିଫଲ୍ଟ `KillMode=process`, କୌଣସି ୟୁନିଟ୍ ବନ୍ଦ କିମ୍ବା ପୁନଃଚାଳୁ ହେଲେ ମଧ୍ୟ `Runner.Worker → npm → next-build`କୁ
ଚାଲୁ ରଖେ — ଏକ ଅନାଥ ବିଲ୍ଡ୍ କୌଣସି ଜବ୍ ସଂଲଗ୍ନ ନ ଥାଇ RAM ଏବଂ
CPU ବ୍ୟବହାର କରିଚାଲେ। ପ୍ରତ୍ୟେକ OmniRoute ୟୁନିଟ୍ରେ
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ଠାରେ `KillMode=mixed` ସହିତ ଏକ ଡ୍ରପ୍-ଇନ୍ ରହିଛି: ପ୍ରଥମେ ଲିସ୍ନର୍କୁ SIGTERM, ଏବଂ
`TimeoutStop` ସମୟରେ ସମ୍ପୂର୍ଣ୍ଣ cgroupକୁ SIGKILL। ୟୁନିଟ୍ର ପରବର୍ତ୍ତୀ ପୁନଃଚାଳନରେ ଏହା କାର୍ଯ୍ୟକାରୀ ହୁଏ — ନିଷ୍କ୍ରିୟତା ଯାଞ୍ଚ ଏବଂ ପୁନଃଚାଳନକୁ ସମାନ କମାଣ୍ଡ୍ରେ ରଖି, **ଏକ ସମୟରେ କେବଳ ଗୋଟିଏ ରନର୍କୁ ଏବଂ କେବଳ ତାହା ନିଷ୍କ୍ରିୟ ଥିବାବେଳେ** ପୁନଃଚାଳୁ କରନ୍ତୁ।
