## janitor ઇન્સ્ટૉલ કરો (એક વખત, સર્વર પર)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): દર 30 મિનિટે, /var/log/runner-janitor.log માં લૉગ કરો
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` આવશ્યક છે: janitor કોઈ પાથને દૂર કરતાં પહેલાં ખુલ્લી ફાઇલોનો એક સ્નૅપશૉટ લઈને સાબિત કરે છે કે તે નિષ્ક્રિય છે, અને આ સાધન વિના તે કશું દૂર કરતું નથી તથા તેવું જણાવે છે (exit 1). કોઈપણ ફેરફાર પહેલાં `--dry-run` સાથે અજમાવો — તે બરાબર શું કરશે તે પ્રિન્ટ કરે છે અને કશામાં ફેરફાર કરતું નથી.

દરેક રનમાં તે શું કરે છે: **tmpfs પર 3 કલાક** અને ડિસ્કના `_work/_temp` પર 24 કલાક પછી આપણા પોતાના અવશેષો (`runner-*`, `omniroute-*`, `next-build*`, `e2e-build.tar.gz`) સાફ કરે છે; 75 મિનિટ કરતાં જૂના `next-build`ને બંધ કરે છે (કોઈ job એટલો લાંબો ચાલતો નથી — 2026-08-27ના રોજ GitHubએ તેનું job ખોવાયેલું જાહેર કર્યા પછી એક 70 મિનિટ ચાલ્યું હતું); જે runnersનું unit **બંધ** હોય તેમના 48 કલાક જૂના checkouts દૂર કરે છે; ડિસ્ક ≥ 85 %, memory PSI `full/avg60` ≥ 10 %, અને `MAX_ACTIVE_RUNNERS` કરતાં વધુ listeners હોય ત્યારે ચેતવણી આપે છે (omniroute/અન્યના વિભાજન સાથે). Exit 1 = ધ્યાન આપવું જરૂરી છે; લૉગ વાંચો.

75-મિનિટનો નિયમ એવા buildને પકડી શકતો નથી જેનું job GitHub પહેલેથી જ છોડી ચૂક્યું હોય. જ્યારે `Runner.Listener` તેનું job નવીનીકૃત કરી શકતું નથી, ત્યારે `_diag/Runner_*.log`માં `POST request to …/renewjob timed out after 100 seconds` દેખાય છે, API છેલ્લા સફળ નવીનીકરણના લગભગ દસ મિનિટ પછી jobને `completed` (failure) તરીકે દર્શાવે છે, અને કોઈ job જોડાયેલું ન હોવા છતાં `next-build` ચાલતું રહે છે (2026-10-18: #17066નું Build 19:43 વાગ્યે નિષ્ફળ થયું હતું અને પાંચ મિનિટ પછી પણ તેનું build 40 GB રોકી રાખતું હતું). સૌથી નવા `_diag/Worker_*.log`માં refની પુષ્ટિ કરો, પછી ફક્ત build treeને PID દ્વારા SIGTERM મોકલો — `next-build`, `npm run build`, `build-next-isolated.mjs` અને `_work` workers. `Runner.Listener`, `RunnerService.js` અથવા `Runner.Worker`ને ક્યારેય સ્પર્શશો નહીં: worker jobને cancelled તરીકે રિપોર્ટ કરે છે અને listener પોતાની મેળે ફરી online થઈ જાય છે.

## Runner units: KillMode

Runnerનું ડિફૉલ્ટ `KillMode=process`, unit બંધ અથવા restart કરવામાં આવે ત્યારે `Runner.Worker → npm → next-build`ને જીવંત છોડી દે છે — જોડાયેલું job ન હોવા છતાં orphan build RAM અને CPU વાપરતું રહે છે. દરેક OmniRoute unitમાં
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
સ્થિત `KillMode=mixed` ધરાવતું drop-in છે: પહેલાં listenerને SIGTERM અને `TimeoutStop` સમયે સમગ્ર cgroupને SIGKILL મોકલે છે. તે unitના આગામી restart વખતે અમલમાં આવે છે — idle check અને restart એક જ commandમાં રાખીને, **એક સમયે ફક્ત એક runnerને અને તે idle હોય ત્યારે જ restart કરો**.
