છે (અગાઉનાં મૂલ્યો `override.conf.bak-20261018` તરીકે રાખવામાં આવ્યા છે) અને તેમને
`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` વડે લાઇવ લાગુ કરવામાં આવી હતી — કોઈ restart નહીં, તેથી
ચાલુ રહેલી કોઈ jobને અસર થઈ નહોતી. લેબલ્સ runners API મારફતે બદલવામાં આવે છે
(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`), તે પણ લાઇવ.

## જેનિટર ઇન્સ્ટૉલ કરો (એક વખત, બૉક્સ પર)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): દર 30 મિનિટે, /var/log/runner-janitor.logમાં લૉગ કરો
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` જરૂરી છે: જેનિટર કોઈ પાથને દૂર કરતાં પહેલાં ખુલ્લી
ફાઇલોનો એક સ્નૅપશૉટ લઈને તે નિષ્ક્રિય છે તે સાબિત કરે છે, અને આ સાધન વિના તે કશું દૂર કરતું નથી તથા એવું જણાવે છે
(exit 1). કોઈપણ ફેરફાર પહેલાં `--dry-run` વડે અજમાવો — તે બરાબર શું કરશે તે બતાવે છે
અને કશાને સ્પર્શતું નથી.

દરેક રન વખતે તે શું કરે છે: **tmpfs પર 3 કલાક** અને ડિસ્કના
`_work/_temp`માં 24 કલાક પછી આપણા પોતાના અવશેષો (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) સાફ કરે છે; 75 મિનિટથી જૂના `next-build`ને બંધ કરે છે (કોઈ જૉબ આટલો લાંબો ચાલતો નથી —
2026-08-27ના રોજ GitHubએ તેનો જૉબ ગુમ થયેલો જાહેર કર્યા પછી એક જૉબ 70 મિનિટ સુધી ચાલ્યો હતો); જેમના યુનિટ **બંધ** છે
તેવા રનરના 48 કલાક જૂના ચેકઆઉટ દૂર કરે છે; ડિસ્ક ≥ 85 %, મેમરી PSI
`full/avg60` ≥ 10 %, અને `MAX_ACTIVE_RUNNERS` કરતાં વધુ લિસનર હોય ત્યારે ચેતવણી આપે છે (સાથે
omniroute/અન્યનું વિભાજન). Exit 1 = ધ્યાન આપવું જરૂરી છે; લૉગ વાંચો.

## રનર યુનિટ્સ: KillMode

રનરનું ડિફૉલ્ટ `KillMode=process`, યુનિટને બંધ અથવા રીસ્ટાર્ટ કરવામાં આવે ત્યારે `Runner.Worker → npm → next-build`ને ચાલુ રાખે છે — કોઈ જોબ જોડાયેલી ન હોવા છતાં અનાથ બિલ્ડ RAM અને CPU વાપરતું રહે છે. દરેક OmniRoute યુનિટમાં
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ડ્રૉપ-ઇન છે, જેમાં `KillMode=mixed` છે: પહેલાં listenerને SIGTERM અને
`TimeoutStop` પર આખા cgroupને SIGKILL. તે યુનિટના આગામી રીસ્ટાર્ટ વખતે અમલમાં આવે છે — **એક સમયે માત્ર એક રનરને, અને તે નિષ્ક્રિય હોય ત્યારે જ રીસ્ટાર્ટ કરો**, તેમજ નિષ્ક્રિયતાની ચકાસણી અને રીસ્ટાર્ટ એક જ કમાન્ડમાં કરો.

## સંચાલન નિયમો

- **એક સમયે માત્ર એક Turbopack build — label દ્વારા અમલમાં મૂકાયેલું.** સંપૂર્ણ Turbopack
  `next build` ચલાવતું દરેક job `[self-hosted, omni-build]` ને લક્ષ્ય બનાવે છે, અને માત્ર **`omniroute-113-5`** પાસે જ તે
  label છે: `ci.yml` `Build`, `npm-publish.yml` `publish`, `nightly-v4-build`, `preview-artifact`,
  રાત્રિકાળીન a11y build (#16853) અને `docker-publish.yml` **amd64** (BuildKitની અંદર webpack —
  ત્યાં Turbopack પૅનિક થયું હતું, run 33253576569). arm64 Docker leg `ubuntu-24.04-arm` પર જ રહે છે.
  `docker-publish` amd64, `ci.yml` `Build` સાથે `heavy-build-main` concurrency group વહેંચે છે
  (`cancel-in-progress: false`). Docker Engine `omniroute-113-5` પર હોવું આવશ્યક છે. બીજો Turbopack
  slot 78 GBમાં સમાતો નથી (2 × 33–37 GB ઉપરાંત બૉક્સની બાકીની જરૂરિયાતો); બીજો slot માત્ર
  webpack builds માટે જ સુરક્ષિત છે.
- **Release-Green પાસે પોતાનો slot છે (2026-10-18).** ત્યાં સુધી બંને Release-Green validations
  `omni-build` પર ચાલતાં હતાં: દરેક push પર (~10/કલાક, એક જ દિવસમાં 100 push runsમાંથી 97 કામની વચ્ચે જ રદ થયા)
  અને દરરોજ ત્રણ ~2 hના સંપૂર્ણ sweeps (05:29ના sweepએ slot માટે 6 h રાહ જોઈ) — એકમાત્ર build
  slot પર તેની ક્ષમતા કરતાં અનેકગણો ભાર હતો અને પોતાના originમાંથી આવેલા PR Buildsને કલાકો રાહ જોવી પડતી હતી.
  `release-green` અને `main-green` હવે `OMNIROUTE_USE_TURBOPACK=0` સાથે
  `omni-release` (માત્ર `omniroute-113-6`) ને લક્ષ્ય બનાવે છે, અને શરૂ થયેલો run હવે નવા pushને કારણે રદ થતો નથી (
  pending slot હજી પણ આ ધસારાને સંકોચે છે). `tests/unit/build/runner-capacity-routing.test.ts`
  routing, webpack switch અને `omni-release` પર કંઈ પણ Turbopack વડે build ન થાય તે નિશ્ચિત કરે છે.
- **હળવો pool: `omni-light`.** `omniroute-113` અને `omniroute-113-2` એવા nightlies ચલાવે છે જેને
  માત્ર backend માટેનું `next build` (~5–6 GB; webpack) અને `quality.yml` `lint-guard` જોઈએ છે. `omniroute-113`
  પર 2026-10-18 સુધી `MemoryHigh=4G` હતું — promptfoo build ત્યાં 54 મિનિટ સુધી reclaim કરતું રહ્યું;
  8 GB throttling દૂર કરે છે.
- **ઇરાદાપૂર્વક ઓછા listeners.** 2026-08-29ના રોજ ચાર OmniRoute units અક્ષમ કરવામાં આવ્યા હતા — દરેક વધારાનો
  listener ઉપરના memory budget માટે વધુ એક tenant છે. janitorની મહત્તમ મર્યાદા 6 છે (`MAX_ACTIVE_RUNNERS=6` cronમાં): તે બૉક્સ પરના
  દરેક `Runner.Listener` ને ગણે છે, અને OmniHeuris + OmniMind આપણા ચાર ઉપરાંત વધુ બે ઉમેરે છે.
