## ਜੈਨਿਟਰ ਇੰਸਟਾਲ ਕਰੋ (ਇੱਕ ਵਾਰ, ਮਸ਼ੀਨ ਉੱਤੇ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ਹਰ 30 ਮਿੰਟ ਬਾਅਦ, ਲੌਗ /var/log/runner-janitor.log ਵਿੱਚ
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ਲਾਜ਼ਮੀ ਹੈ: ਜੈਨਿਟਰ ਕਿਸੇ ਪਾਥ ਨੂੰ ਹਟਾਉਣ ਤੋਂ ਪਹਿਲਾਂ ਖੁੱਲ੍ਹੀਆਂ
ਫ਼ਾਈਲਾਂ ਦੇ ਇੱਕ ਸਨੈਪਸ਼ਾਟ ਨਾਲ ਸਾਬਤ ਕਰਦਾ ਹੈ ਕਿ ਉਹ ਨਿਸ਼ਕਿਰਿਆ ਹੈ, ਅਤੇ ਇਸ ਟੂਲ ਤੋਂ ਬਿਨਾਂ ਇਹ ਕੁਝ ਵੀ ਨਹੀਂ ਹਟਾਉਂਦਾ ਅਤੇ ਅਜਿਹਾ ਦੱਸਦਾ ਹੈ
(exit 1)। ਕਿਸੇ ਵੀ ਤਬਦੀਲੀ ਨੂੰ ਪਹਿਲਾਂ `--dry-run` ਨਾਲ ਅਜ਼ਮਾਓ — ਇਹ ਬਿਲਕੁਲ ਉਹੀ ਪ੍ਰਿੰਟ ਕਰਦਾ ਹੈ ਜੋ ਇਹ
ਕਰੇਗਾ ਅਤੇ ਕਿਸੇ ਚੀਜ਼ ਨੂੰ ਛੂੰਹਦਾ ਨਹੀਂ।

ਇਹ ਹਰ ਰਨ ਦੌਰਾਨ ਕੀ ਕਰਦਾ ਹੈ: **tmpfs ਉੱਤੇ 3 ਘੰਟਿਆਂ** ਅਤੇ ਡਿਸਕ ਉੱਤੇ
`_work/_temp` ਵਿੱਚ 24 ਘੰਟਿਆਂ ਬਾਅਦ ਸਾਡੇ ਆਪਣੇ ਬਚੇ ਹੋਏ ਅੰਸ਼ਾਂ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) ਨੂੰ ਸਾਫ਼ ਕਰਦਾ ਹੈ; 75 ਮਿੰਟ ਤੋਂ ਪੁਰਾਣੇ `next-build` ਨੂੰ ਖਤਮ ਕਰਦਾ ਹੈ (ਕੋਈ ਜੌਬ ਇੰਨਾ ਲੰਮਾ ਨਹੀਂ ਚੱਲਦਾ —
2026-08-27 ਨੂੰ GitHub ਵੱਲੋਂ ਉਸ ਦੀ ਜੌਬ ਨੂੰ ਗੁੰਮ ਐਲਾਨਣ ਤੋਂ ਬਾਅਦ ਇੱਕ ਜੌਬ 70 ਮਿੰਟ ਤੱਕ ਚੱਲਿਆ ਸੀ);
ਉਨ੍ਹਾਂ ਰਨਰਾਂ ਦੇ 48 ਘੰਟੇ ਪੁਰਾਣੇ ਚੈੱਕਆਉਟ ਹਟਾਉਂਦਾ ਹੈ ਜਿਨ੍ਹਾਂ ਦੀ ਯੂਨਿਟ **ਬੰਦ** ਹੈ; ਡਿਸਕ ≥ 85 %, ਮੈਮੋਰੀ PSI
`full/avg60` ≥ 10 %, ਅਤੇ `MAX_ACTIVE_RUNNERS` ਤੋਂ ਵੱਧ ਲਿਸਨਰ ਹੋਣ ਉੱਤੇ ਚੇਤਾਵਨੀ ਦਿੰਦਾ ਹੈ (omniroute/ਹੋਰ
ਵੰਡ ਸਮੇਤ)। Exit 1 = ਧਿਆਨ ਦੇਣ ਦੀ ਲੋੜ ਹੈ; ਲੌਗ ਪੜ੍ਹੋ।

75-ਮਿੰਟ ਵਾਲਾ ਨਿਯਮ ਉਸ ਬਿਲਡ ਨੂੰ ਨਹੀਂ ਫੜਦਾ ਜਿਸ ਦੀ ਜੌਬ ਨੂੰ GitHub ਪਹਿਲਾਂ ਹੀ ਛੱਡ ਚੁੱਕਾ ਹੋਵੇ। ਜਦੋਂ
`Runner.Listener` ਆਪਣੀ ਜੌਬ ਨੂੰ ਰੀਨਿਊ ਨਹੀਂ ਕਰ ਸਕਦਾ, ਤਾਂ `_diag/Runner_*.log` ਵਿੱਚ
`POST request to …/renewjob timed out after 100 seconds` ਦਿਖਾਈ ਦਿੰਦਾ ਹੈ, API ਆਖਰੀ ਸਫਲ ਰੀਨਿਊਅਲ ਤੋਂ ਲਗਭਗ ਦਸ ਮਿੰਟ ਬਾਅਦ ਜੌਬ ਨੂੰ `completed`
(ਅਸਫਲ) ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ, ਅਤੇ `next-build` ਬਿਨਾਂ ਕਿਸੇ ਜੁੜੀ ਹੋਈ ਜੌਬ ਦੇ ਚੱਲਦਾ ਰਹਿੰਦਾ ਹੈ
(2026-10-18: #17066 ਦਾ ਬਿਲਡ 19:43 ਉੱਤੇ ਅਸਫਲ ਹੋ ਗਿਆ ਸੀ ਅਤੇ ਉਸ ਦਾ ਬਿਲਡ ਪੰਜ ਮਿੰਟ ਬਾਅਦ ਵੀ
40 GB ਘੇਰੀ ਬੈਠਾ ਸੀ)। ਸਭ ਤੋਂ ਨਵੇਂ `_diag/Worker_*.log` ਵਿੱਚ ਰੈਫ ਦੀ ਪੁਸ਼ਟੀ ਕਰੋ, ਫਿਰ
PID ਰਾਹੀਂ ਸਿਰਫ਼ ਬਿਲਡ ਟ੍ਰੀ ਨੂੰ SIGTERM ਭੇਜੋ — `next-build`, `npm run build`, `build-next-isolated.mjs` ਅਤੇ
`_work` ਵਰਕਰ। `Runner.Listener`, `RunnerService.js` ਜਾਂ `Runner.Worker` ਨੂੰ ਕਦੇ ਨਾ ਛੂਹੋ:
ਵਰਕਰ ਜੌਬ ਨੂੰ ਰੱਦ ਹੋਈ ਵਜੋਂ ਰਿਪੋਰਟ ਕਰਦਾ ਹੈ ਅਤੇ ਲਿਸਨਰ ਆਪਣੇ ਆਪ ਮੁੜ ਆਨਲਾਈਨ ਹੋ ਜਾਂਦਾ ਹੈ।

## ਰਨਰ ਯੂਨਿਟਾਂ: KillMode

ਰਨਰ ਦਾ ਡਿਫੌਲਟ `KillMode=process`, ਯੂਨਿਟ ਬੰਦ ਜਾਂ ਰੀਸਟਾਰਟ ਹੋਣ ਉੱਤੇ
`Runner.Worker → npm → next-build` ਨੂੰ ਚੱਲਦਾ ਛੱਡ ਦਿੰਦਾ ਹੈ — ਇੱਕ ਅਨਾਥ ਬਿਲਡ ਬਿਨਾਂ ਕਿਸੇ ਜੁੜੀ ਹੋਈ ਜੌਬ ਦੇ RAM ਅਤੇ
CPU ਵਰਤਦਾ ਰਹਿੰਦਾ ਹੈ। ਹਰ OmniRoute ਯੂਨਿਟ ਵਿੱਚ ਇੱਕ ਡਰੌਪ-ਇਨ
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ਹੁੰਦਾ ਹੈ ਜਿਸ ਵਿੱਚ `KillMode=mixed` ਹੈ: ਪਹਿਲਾਂ ਲਿਸਨਰ ਨੂੰ SIGTERM, ਫਿਰ
