OmniRoute రన్నర్కు **ఒక పాత్ర**, ఒక లేబుల్, అలాగే దాని వర్క్లోడ్లో కొలిచిన వినియోగానికి తగిన మెమరీ/CPU బడ్జెట్

`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…`తో ప్రత్యక్షంగా వర్తింపజేయబడ్డాయి — restart చేయలేదు, కాబట్టి

(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`).

## janitorను ఇన్స్టాల్ చేయండి (ఒక్కసారి మాత్రమే, సర్వర్లో)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ప్రతి 30 నిమిషాలకు, /var/log/runner-janitor.logలో లాగ్ చేయండి
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` అవసరం: ఒక పాత్ను తొలగించే ముందు తెరిచి ఉన్న ఫైళ్ల యొక్క ఒక స్నాప్షాట్తో
అది నిష్క్రియగా ఉందని janitor నిర్ధారిస్తుంది; ఈ సాధనం లేకపోతే అది దేనినీ తొలగించదు
మరియు ఆ విషయాన్ని తెలియజేస్తుంది (exit 1). ఏ మార్పునైనా ముందుగా `--dry-run`తో
ప్రయత్నించండి — అది ఏం చేస్తుందో ఖచ్చితంగా ప్రింట్ చేస్తుంది, దేనినీ మార్చదు.

ప్రతి రన్లో ఇది చేసేవి: **tmpfsలో 3 గంటల** తర్వాత మరియు డిస్క్లోని
`_work/_temp`లో 24 గంటల తర్వాత మన స్వంత అవశేషాలను (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) తొలగిస్తుంది; 75 నిమిషాల కంటే పాతదైన
`next-build`ను నిలిపివేస్తుంది (ఏ job కూడా అంతసేపు రన్ అవదు — 2026-08-27న
GitHub దాని job పోయిందని ప్రకటించిన తర్వాత కూడా ఒకటి 70 నిమిషాలు రన్ అయింది);
వాటి unit **stopped** స్థితిలో ఉన్న runnersకు చెందిన 48 గంటల పాత checkoutsను
తొలగిస్తుంది; డిస్క్ ≥ 85 %, మెమరీ PSI `full/avg60` ≥ 10 %, మరియు
`MAX_ACTIVE_RUNNERS` కంటే ఎక్కువ listeners ఉన్నప్పుడు (omniroute/other విభజనతో)
హెచ్చరిస్తుంది. Exit 1 = శ్రద్ధ అవసరం; లాగ్ను చదవండి.

GitHub ఇప్పటికే వదులుకున్న jobకు చెందిన buildను 75 నిమిషాల నియమం గుర్తించదు.
`Runner.Listener` తన jobను పునరుద్ధరించలేనప్పుడు, `_diag/Runner_*.log`లో
`POST request to …/renewjob timed out after 100 seconds` కనిపిస్తుంది; చివరి విజయవంతమైన
పునరుద్ధరణ తర్వాత సుమారు పది నిమిషాలకు API ఆ jobను `completed` (failure)గా నివేదిస్తుంది,
మరియు ఏ job జోడించబడకుండానే `next-build` రన్ అవుతూనే ఉంటుంది (2026-10-18న: #17066
యొక్క Build 19:43కు విఫలమైంది, కానీ ఐదు నిమిషాల తర్వాత కూడా దాని build 40 GBని
ఆక్రమించి ఉంచింది). అత్యంత కొత్త `_diag/Worker_*.log`లో refను నిర్ధారించి, ఆపై PID
ఆధారంగా build treeకు మాత్రమే SIGTERM పంపండి — `next-build`, `npm run build`,
`build-next-isolated.mjs` మరియు `_work` workers. `Runner.Listener`,
`RunnerService.js` లేదా `Runner.Worker`ను ఎప్పుడూ తాకవద్దు: worker ఆ jobను
రద్దయినదిగా నివేదిస్తుంది, listener స్వయంగా మళ్లీ ఆన్లైన్లోకి వస్తుంది.

## Runner units: KillMode

Runner యొక్క డిఫాల్ట్ `KillMode=process`, unitను నిలిపివేసినప్పుడు లేదా
పునఃప్రారంభించినప్పుడు `Runner.Worker → npm → next-build`ను సజీవంగా ఉంచుతుంది —
ఏ job జోడించబడని orphan build RAM మరియు CPUని వినియోగిస్తూనే ఉంటుంది. ప్రతి
OmniRoute unitలో `KillMode=mixed`తో ఒక drop-in
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
ఉంటుంది: మొదట listenerకు SIGTERM, `TimeoutStop` వద్ద మొత్తం cgroupకు SIGKILL
పంపుతుంది. Unit తదుపరి పునఃప్రారంభంలో ఇది అమల్లోకి వస్తుంది — **ఒకేసారి ఒక
runnerను మాత్రమే, అది నిష్క్రియగా ఉన్నప్పుడు మాత్రమే** పునఃప్రారంభించండి; idle
తనిఖీ మరియు restart ఒకే commandలో ఉండాలి.
