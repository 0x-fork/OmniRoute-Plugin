## გამწმენდის დაყენება (ერთჯერადად, სერვერზე)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ყოველ 30 წუთში, ჟურნალი ჩაიწეროს /var/log/runner-janitor.log-ში
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` აუცილებელია: წაშლამდე გამწმენდი ღია ფაილების ერთი სნეპშოტით ადასტურებს,
რომ ბილიკი უმოქმედოა; ამ ხელსაწყოს გარეშე კი არაფერს შლის და ამის შესახებ
შეტყობინებას გამოჰყავს (exit 1). ნებისმიერი ცვლილება ჯერ `--dry-run`-ით სცადეთ —
ის ზუსტად დაბეჭდავს, რას გააკეთებდა, და არაფერს შეცვლის.

ყოველი გაშვებისას ის: ასუფთავებს ჩვენსავე ნარჩენებს (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) **tmpfs-ზე 3 სთ-ის**, ხოლო დისკზე
`_work/_temp`-ში 24 სთ-ის შემდეგ; ასრულებს 75 წუთზე ძველ `next-build`-ს
(არცერთი დავალება ამდენ ხანს არ მუშაობს — 2026-08-27-ს ერთ-ერთი 70 წუთის
განმავლობაში მუშაობდა მას შემდეგ, რაც GitHub-მა მისი დავალება დაკარგულად
გამოაცხადა); შლის 48 საათის წინანდელ checkout-ებს იმ რანერებისთვის, რომელთა
unit-იც **გაჩერებულია**; აგზავნის გაფრთხილებას, თუ დისკის გამოყენება ≥ 85 %-ია,
მეხსიერების PSI `full/avg60` ≥ 10 %-ია, ან listener-ების რაოდენობა
`MAX_ACTIVE_RUNNERS`-ს აღემატება (omniroute/other დაყოფით). Exit 1 = საჭიროა
ყურადღება; წაიკითხეთ ჟურნალი.

75-წუთიანი წესი ვერ აფიქსირებს ბილდს, რომლის დავალებაზეც GitHub-მა უკვე ხელი
ჩაიქნია. როდესაც `Runner.Listener` საკუთარ დავალებას ვეღარ აახლებს,
`_diag/Runner_*.log`-ში ჩანს
`POST request to …/renewjob timed out after 100 seconds`, API კი ბოლო წარმატებული
განახლებიდან დაახლოებით ათი წუთის შემდეგ დავალებას `completed`-ად (failure)
აცხადებს, ხოლო `next-build` მიმაგრებული დავალების გარეშე აგრძელებს მუშაობას

`_diag/Worker_*.log`-ში, შემდეგ კი PID-ის მიხედვით SIGTERM გაუგზავნეთ მხოლოდ

## რანერის unit-ები: KillMode

რანერის ნაგულისხმევი `KillMode=process` unit-ის გაჩერების ან გადატვირთვისას
`Runner.Worker → npm → next-build`-ს გაშვებულს ტოვებს — ობოლი ბილდი მიმაგრებული
დავალების გარეშე აგრძელებს RAM-ისა და CPU-ის მოხმარებას. OmniRoute-ის ყველა
unit-ს აქვს drop-in
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
`KillMode=mixed`-ით: ჯერ SIGTERM listener-ს, ხოლო `TimeoutStop`-ის დადგომისას
SIGKILL მთელ cgroup-ს. ის ძალაში შევა unit-ის შემდეგი გადატვირთვისას —
გადატვირთეთ **თითო რანერი ერთ ჯერზე და მხოლოდ მაშინ, როდესაც უმოქმედოა**;
უმოქმედობის შემოწმება და გადატვირთვა ერთსა და იმავე ბრძანებაში შეასრულეთ.
