(മുമ്പത്തെ മൂല്യങ്ങൾ `override.conf.bak-20261018` ആയി സൂക്ഷിച്ചിട്ടുണ്ട്), കൂടാതെ
`systemctl set-property --runtime … MemoryHigh=… MemoryMax=… CPUQuota=…` ഉപയോഗിച്ച് അവ പ്രവർത്തനത്തിനിടെ പ്രയോഗിച്ചു — പുനരാരംഭിച്ചില്ല, അതിനാൽ
പ്രവർത്തിച്ചുകൊണ്ടിരുന്ന ഒരു ജോബിനെയും ബാധിച്ചില്ല. runners API വഴിയാണ് ലേബലുകൾ മാറ്റുന്നത്
(`gh api -X DELETE repos/<repo>/actions/runners/<id>/labels/<label>` /
`gh api -X POST repos/<repo>/actions/runners/<id>/labels -f 'labels[]=<label>'`), അതും പ്രവർത്തനത്തിനിടെ തന്നെയാണ്.

## ജാനിറ്റർ ഇൻസ്റ്റാൾ ചെയ്യുക (ഒറ്റത്തവണ, ബോക്സിൽ)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ഓരോ 30 മിനിറ്റിലും, /var/log/runner-janitor.log-ലേക്ക് ലോഗ് ചെയ്യുക
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` ആവശ്യമാണ്: ഒരു പാത്ത് നീക്കം ചെയ്യുന്നതിന് മുമ്പ് തുറന്നിരിക്കുന്ന
ഫയലുകളുടെ ഒറ്റ സ്നാപ്പ്ഷോട്ട് ഉപയോഗിച്ച് അത് നിഷ്ക്രിയമാണെന്ന് ജാനിറ്റർ ഉറപ്പാക്കുന്നു; ഈ ടൂൾ ഇല്ലെങ്കിൽ അത്
ഒന്നും നീക്കം ചെയ്യാതെ അക്കാര്യം അറിയിക്കുന്നു
(exit 1). ഏത് മാറ്റവും ആദ്യം `--dry-run` ഉപയോഗിച്ച് പരീക്ഷിക്കുക — അത് എന്താണ് ചെയ്യാൻ പോകുന്നതെന്ന്
കൃത്യമായി പ്രിന്റ് ചെയ്യുകയും ഒന്നിലും മാറ്റം വരുത്താതിരിക്കുകയും ചെയ്യുന്നു.

ഓരോ റണ്ണിലും ഇത് ചെയ്യുന്നത്: **tmpfs-ൽ 3 മണിക്കൂർ** കഴിഞ്ഞതും ഡിസ്കിലെ
`_work/_temp`-ൽ 24 മണിക്കൂർ കഴിഞ്ഞതുമായ നമ്മുടെ സ്വന്തം ശേഷിപ്പുകൾ (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) നീക്കം ചെയ്യുന്നു; 75 മിനിറ്റിൽ കൂടുതൽ പഴക്കമുള്ള ഒരു `next-build`
നിർത്തുന്നു (ഒരു ജോലിയും അത്രയും നേരം പ്രവർത്തിക്കില്ല — 2026-08-27-ന് GitHub അതിന്റെ ജോലി
നഷ്ടപ്പെട്ടതായി പ്രഖ്യാപിച്ചതിനുശേഷവും ഒരെണ്ണം 70 മിനിറ്റ് പ്രവർത്തിച്ചു); യൂണിറ്റ് **നിർത്തിയിട്ടുള്ള**
റണ്ണറുകളുടെ 48 മണിക്കൂർ പഴക്കമുള്ള ചെക്കൗട്ടുകൾ നീക്കം ചെയ്യുന്നു; ഡിസ്ക് ≥ 85 %, മെമ്മറി PSI
`full/avg60` ≥ 10 %, `MAX_ACTIVE_RUNNERS`-നേക്കാൾ കൂടുതൽ ലിസണറുകൾ എന്നിവയിൽ
(omniroute/മറ്റുള്ളവ എന്ന വിഭജനത്തോടെ) മുന്നറിയിപ്പ് നൽകുന്നു. Exit 1 = ശ്രദ്ധ ആവശ്യമാണ്; ലോഗ് വായിക്കുക.

## റണ്ണർ യൂണിറ്റുകൾ: KillMode

ഒരു യൂണിറ്റ് നിർത്തുകയോ പുനരാരംഭിക്കുകയോ ചെയ്യുമ്പോൾ റണ്ണറിന്റെ ഡിഫോൾട്ട് `KillMode=process`, `Runner.Worker → npm → next-build`
എന്നതിനെ പ്രവർത്തിച്ചുകൊണ്ടിരിക്കാൻ അനുവദിക്കുന്നു — ഒരു ജോലിയുമായും ബന്ധിപ്പിക്കാത്ത അനാഥ ബിൽഡ് RAM-ഉം
CPU-വും ഉപയോഗിച്ചുകൊണ്ടിരിക്കും. ഓരോ OmniRoute യൂണിറ്റിലും
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
എന്ന drop-in ഉണ്ട്; അതിൽ `KillMode=mixed` ആണ്: ആദ്യം listener-ലേക്ക് SIGTERM, തുടർന്ന്
`TimeoutStop`-ൽ മുഴുവൻ cgroup-ലേക്കും SIGKILL. യൂണിറ്റിന്റെ അടുത്ത പുനരാരംഭത്തിൽ ഇത് പ്രാബല്യത്തിൽ വരും — **ഒരു സമയം
ഒരു റണ്ണർ മാത്രം, അത് idle ആയിരിക്കുമ്പോൾ മാത്രം** പുനരാരംഭിക്കുക; idle പരിശോധനയും പുനരാരംഭവും ഒരേ command-ൽ നടത്തണം.

- **ഒരേസമയം ഒരു Turbopack build മാത്രം — ലേബൽ വഴി നിർബന്ധമാക്കിയിരിക്കുന്നു.** പൂർണ്ണ Turbopack
  `next build` പ്രവർത്തിപ്പിക്കുന്ന എല്ലാ job-കളും `[self-hosted, omni-build]` ലക്ഷ്യമിടുന്നു; ആ
  ലേബൽ ഉള്ളത് **`omniroute-113-5`**-ന് മാത്രം: `ci.yml` `Build`, `npm-publish.yml` `publish`,
  `nightly-v4-build`, `preview-artifact`, രാത്രികാല a11y build (#16853), കൂടാതെ
  `docker-publish.yml` **amd64** (BuildKit-നുള്ളിലെ webpack — അവിടെ Turbopack panic സംഭവിച്ചു,
  run 33253576569). arm64 Docker ഘട്ടം `ubuntu-24.04-arm`-ൽ തന്നെ തുടരുന്നു.
  `docker-publish` amd64, `ci.yml` `Build`-നൊപ്പം `heavy-build-main` concurrency group
